# HARNESS — запуск конвейера в Claude Code

Это промт-вводная. Кинь его целиком в Claude Code в корне репозитория — и он развернёт и соберёт **один урок** из плана, автономно, с самопроверкой, останавливаясь на том, что требует человека.

---

**Ты — сборочный харнесс этого репозитория.** Собираешь один урок AMC 8 за прогон, по плану, с жёстким контролем качества. Инструкции ниже.

## 0. Подготовка (один раз)
- Работай в корне репозитория — здесь лежит `CLAUDE.md`. Прочитай его и файлы `_system/*` (правила, скелет урока, станок, концовка, стиль картинок, QC, Zoom).
- Проверь зависимости: `python-pptx` (проверялка деки), `node` + `pptxgenjs` (сборка `.pptx`). Нет — поставь по `GITHUB.md`. Для шага 00 (OCR буклетов) — poppler + tesseract.
- Если нет `syllabus.json` — построй план: `python harness.py plan`.

## 1. Выбери урок
- Посмотри `python harness.py status`. По умолчанию бери первый со статусом «не начат».
- Либо возьми номер N, который назвал пользователь.

## 2. Разверни структуру
```
python harness.py new N
```
Создаст папку урока и напечатает **БРИФ**: проход, полоса сложности, станок, тип. Дальше действуй строго по брифу.

## 3. Сгенерируй урок
Пиши файлы **в папку урока**, по порядку. Для каждого шага открой соответствующий промт и выполни его:

| Промт | Пишет |
|---|---|
| `_prompts/02-lesson-core.md` | `lesson.md`, `01`, `02`, `07`, `08` |
| `_prompts/03-tasks.md` | `03-zadachi.md`, `04-resheniya.md` |
| ⛔ `_prompts/04-qc.md` | **ШЛЮЗ** (см. ниже) |
| `_prompts/05-slide-texts.md` | `05-slides.md` |
| `_prompts/06-image-prompts.md` | `06-image-prompts.md` |
| `_prompts/07-build-deck.md` | `deck.js` |

**⛔ QC-шлюз (шаг 04):** напиши Python-скрипт, который решает КАЖДУЮ задачу урока с нуля, и сверь с заявленным ответом. Правь или заменяй задачи (переодетой реальной AMC), пока отчёт не станет полностью ✅. **Не переходи к шагу 05, пока шлюз не зелёный.**

**Математика — вектором:** сетки, фигуры, доски, координаты рисуй в `deck.js` через `lib/deckkit.js` (`K.grid`, `K.tile`, `K.chessboard`, `K.nestedSquares`). Картинки — только атмосфера, без цифр. В `deck.js` используй `K.artOrBg`, чтобы дека собиралась и без картинок.

## 4. Собери и проверь
```
python harness.py check N
```
Соберёт `deck.pptx`, прогонит валидатор, покажет чек-лист и вердикт. Если файл — «болванка» или дека не собралась, вернись к шагу 3 и доделай. Числа на векторных диаграммах глазами сверь с условиями.

## 5. Останов на человека
- **Картинки** генерит человек (GPT Image по `06-image-prompts.md`) и кладёт в `<урок>/img/` как `img-01.png` … После этого повтори `python harness.py check N` — дека пересоберётся с картинками.
- **Пробники и мок-тесты** (уроки типа ПРОБНИК/ОБЗОР-мок) — из реальных прошлых AMC (AoPS), **не генерировать**.

## 6. Зафиксируй
```
git checkout -b urok-NN
git add -A && git commit -m "Урок NN: <тема>"
git push -u origin urok-NN
```

## Правила харнесса (не нарушать)
1. **Один урок за прогон.** Собрал → доложил → жди следующего. Не гони все 36 сразу.
2. **QC — жёсткий шлюз** с авто-циклом правок; ответы проверяются счётом, не перечитыванием.
3. **Математика — вектором** в `deck.js`; картинки — атмосфера.
4. **Проход 2/3** одной темы: тот же приём и карточка, задачи из полосы AMC выше, разминкой — интерливинг прошлого прохода.
5. **Пробники — реальные**, не генерировать.
6. **Задача раньше правила**, приём с именем, финал чистый и легче основной, крючок после победы.
7. В заметках титульного слайда деки — «шарить окно, не экран».

## Доклад в конце прогона
Коротко: какой урок собран, прошёл ли QC, какие файлы ещё болванки, сколько картинок нужно сгенерировать, и команда коммита.

### Быстрый старт (первый урок)
```
python harness.py plan          # если ещё не построен
python harness.py status        # увидеть план
python harness.py new 1         # развернуть урок 1 + бриф

python harness.py check 1       # собрать деку + проверить
```
