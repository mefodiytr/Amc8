# shablon-prezentacii.md — болванка презентации

> Заполняется промтом `4-prezentaciya` → файл `05-prezentaciya.md`. Формат повторяет эталон
> `_referensy/amc8_bob_slides.md`. Текста на слайде намеренно мало — суть проговаривается
> вслух в заметках докладчику. Принцип «задача раньше теории» вшит в заметки.

---

## Формат каждого слайда

```
### Слайд K — <короткий заголовок>
**Заголовок:** <крупная фраза на слайде>
**На слайде:** <минимум текста — числа, улики, ключевая строка; НЕ абзацы>
**Картинка:** <ссылка на кадр из 06: Акт 1/2/3, либо «—» / простая схема>
**Заметка докладчику:** <что сказать вслух; какой вопрос задать ДО показа следующего шага>
```

## Драматургия (по эталону Боба, 8–10 слайдов на 7–10 минут)

1. **Титул** — название «дела», модуль.
2. **Досье/условие** — улики/условие задачи; вопрос «как сузить перебор?», пауза.
3. **Перевод условия в инструмент** — каждая улика = инструмент, который что-то отсекает.
4. **Проходы по решению** (несколько слайдов) — на каждом докладчик СНАЧАЛА задаёт вопрос,
   ученица отвечает, и ТОЛЬКО ПОТОМ слайд показывает следующий шаг. Порядок не нарушать —
   в этом вся методика.
5. **Момент «правило после задачи»** — именно здесь вводится приём/признак, не раньше.
6. **Развязка** — ответ, прошедший все проверки (это доказательство, а не везение).
7. **Вынос приёма** — «воронка»/общий принцип, важнее самого ответа.
8. **Трюк в тетрадь** — карточка приёмов (связь с `methodika.md §4`).
9. **Спарринг «попробуй сам»** — новая задача того же типа; ответ — в заметке `[ДЛЯ УЧИТЕЛЯ]`.

## Правила

- Один слайд — одна мысль; текст минимум, детали — в заметках.
- Решения раскрываются ПОШАГОВО (по лесенке подсказок из `04`), не сразу целиком.
- Картинки серии встают на ключевые слайды (условие → Акт 1, сужение → Акт 2, ответ → Акт 3);
  остальные — простой схемой или без иллюстрации.
- Шаблон переиспользуется для другой задачи модуля: меняешь условие и числа, структура остаётся.
